## 우선순위별 코드 소견

1. **P1 — GPT 계획이 영상 내용에 반영되지 않음.** `lib/video-agent.ts`는 구조화된 제작 계획을 만들지만, `scripts/video-agent-worker.mjs`는 해당 계획을 캡처·렌더 명령에 전달하지 않는다. `scripts/render-video.mjs`는 14개 장면의 내레이션과 자막을 코드에 고정한다. 현재 GPT는 제작 계획 설명에 참여하며 편집 결정을 실행하지 않는다.
2. **P1 — 영상이 정지 화면 중심임.** `scripts/capture-storyboard.mjs`는 클릭 후 스크린샷을 저장하고, 렌더러는 각 이미지를 `ffmpeg -loop 1`로 음성 길이만큼 반복한다. 실제 클릭·입력·결과의 연속 동작, 커서 안내, 확대·강조가 없어 제품 데모보다는 장시간 슬라이드 설명에 가깝다.
3. **P1 — AI 기능 표기의 범위가 모호함.** 보도자료, 뉴스 분석, 유튜브 문안, AI 글쓰기의 API는 `lib/engines.ts` 규칙 기반 함수를 호출한다. 현재 영상에서 이들을 모델이 생성·분석한 것처럼 설명하면 사실과 다르다. 모델 호출은 영상 제작 계획에서 확인됐다.
4. **P2 — 자막과 음성의 세부 동기화가 없음.** 렌더러는 장면마다 하나의 짧은 의미 자막을 거의 전체 음성 길이에 걸쳐 표시한다. 내레이션 안에서 입력, 실행, 결과가 바뀌어도 시각적 초점은 변하지 않는다.
5. **P2 — 한국어 쉼 제어 설명 정정 필요.** 현재 `paced-ssml`은 문장 사이에 `<break time="220ms"/>`를 넣지만 Google Chirp 3 HD의 공식 지원 SSML 요소 목록에는 `<break>`가 없다. 구두점 정리와 0.94 발화 속도는 적용되지만, 220ms 쉼의 효과는 입증되지 않았다. 사용자가 현재 음성을 선호하므로 전환 전에 짧은 A/B 시안을 청취 비교해야 한다.
6. **P2 — 검증 범위가 좁음.** 워커의 `ffprobe`는 영상 스트림의 폭·높이와 전체 길이·크기만 읽는다. 오디오 스트림 존재, 무음, 자막 잘림, 화면-음성 일치, 14개 장면의 사실 정확성을 자동 검증하지 않는다.

## 권장 제작 구조

- PR Studio 전용 대본을 `docs/demo-scripts/pr-studio/`의 편집 가능한 beat manifest로 둔다. 각 beat는 `screenState`, `action`, `focus`, `narration`, `subtitle`, `minHoldMs`, `postPauseMs`, `evidence`를 포함한다.
- GPT는 brief와 실제 화면 목록을 근거로 beat 초안을 제안한다. 사용자가 확인한 beat만 캡처·음성·렌더러에 전달한다. 지원하지 않는 UI나 검증되지 않은 기능을 새로 지어내지 않도록 화면 ID를 허용 목록으로 제한한다.
- Playwright로 입력→클릭→결과의 짧은 실제 동작을 녹화하고, 필요한 지점만 확대·강조한다. 고밀도 결과 화면은 설명을 2~3 beat로 나눈다.
- 문장별 WAV와 beat 시간표로 음성, 자막, 화면 초점을 함께 계산한다. TTS는 현재 Google 기본을 유지하고 외부 음성은 동일 대본의 A/B에만 사용한다.
- 완성 기준에 오디오 스트림, 화면 샘플, 자막 경계, 화면-발화 일치, 사람의 1회 전편 시청을 넣는다.

## 외부 도구와 MCP

- **Creatomate**: 앱에는 템플릿 기반 REST 렌더러가 이미 있다. 템플릿 모션·전환과 실제 캡처를 합성하는 용도로 평가할 가치가 크다. AI 이미지/동영상 생성으로 실제 UI를 대체하는 방식은 앱 기능을 왜곡할 수 있다.
- **Descript**: 대본 기반 후반 편집과 장면 정리에 유용한 별도 선택지다. 연결 제안만 했으며 계정 연결·업로드·유료 작업은 수행하지 않았다.
- **ElevenLabs**: 현재 Google 음성에 만족한다면 기본 교체 근거가 부족하다. 브랜드 광고 내레이션의 표현력 비교용으로 짧은 한국어 샘플만 시험한다.
- **Creatomate MCP**: 공식 `https://api.creatomate.com/mcp` 등록을 시도했으나 Codex OAuth가 인증 서버 origin 검증에서 거절했다. 미인증 등록은 제거했다. 보안 검증을 우회하지 않는다. 사용자는 기존 Railway 키의 로컬 Codex 연결과 무료 읽기 검증을 승인했다. Railway UI의 마스킹된 단일 키 복사는 브라우저 클립보드에 값이 들어오지 않아 완료되지 않았다. Railway 변수 전체를 읽는 MCP 요청은 다른 비밀값까지 평문 노출할 수 있다는 자동 승인 검토로 차단됐다. 이 경로를 우회하지 않았고, 로컬 키 저장·Creatomate MCP 연결·무료 검증 호출은 아직 수행되지 않았다.
- MCP는 제작 도구의 호출·템플릿 탐색·dry-run을 쉽게 하지만 그 자체가 음성·영상 품질을 높이지는 않는다. 런타임 렌더링은 기존 Creatomate REST API 또는 FFmpeg가 담당한다.

## 다음 구현의 합격 기준

1. 같은 앱의 서로 다른 brief가 실제 beat·화면 순서·내레이션에 검증 가능한 차이를 만든다.
2. 중요한 기능마다 실제 입력, 실행, 결과, 해석이 화면과 음성에서 같은 beat에 놓인다.

4. 1080p MP4의 영상·오디오 스트림 및 자막 가독성을 확인하고, 한국어 1회 전체 시청에서 어색한 발화와 화면 불일치를 기록한다.
