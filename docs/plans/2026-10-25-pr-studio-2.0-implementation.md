# PR Studio 2.0 구현 계획 (2026-10-25)

## 기준

- 작업 위치: `D:\Worktrees\active\pr-studio\video-2.0`
- 브랜치: `agent/pr-studio-2.0` (기준 커밋 `cb2fe71`, 상위 브랜치 추적 없음)
- 이 문서는 구현 계획이다. 커밋, 푸시, Railway 배포는 별도 지시가 있을 때 한다.
- 기획은 AI가 한다. 앱은 자료를 모아 보고하고, 제작 실행 지시가 있을 때만 촬영·합성한다.

## 한 작업의 순환

1. 사용자가 목적, 길이, 대략 내용을 준다. 비어 있는 값은 그 영상 종류의 기본값을 쓴다.
2. 1차 요청에는 가진 자료를 함께 넣는다. 브리프, 종류별 기본값, 화면 목록, 입력 예시, 앱이 쓸 수 있는 도구 목록이다.
3. AI가 목적, 길이, 장면 윤곽을 정하고 수집 지시를 적는다. 지시 문장은 정해진 동사 목록으로 제한하지 않는다.
4. 앱이 지시를 실행한다. 할 수 있으면 결과와 함께 `있음`으로 보고하고, 할 수 없으면 `없음`으로 보고한다.
5. AI는 그 보고를 보고 내용을 고치거나, 추가 수집을 지시하거나, 제작 실행을 지시한다.
6. `decision`이 `produce`일 때만 워커가 그 기획의 요지, 내레이션, 자막으로 녹화하고 합성한다.

기획 모델 호출은 한 작업당 최대 3회다. 이 상한은 지시 문장을 거르는 규칙이 아니다. 같은 작업이 Railway에서 끝나게 하는 한계다. 3회 안에 `produce`가 없으면 영상을 만들지 않고, 기획과 `없음` 보고만 저장한다.

## 두 가지 기획 입력

| 입력 | 1차 요청에 넣는 것 | 원본을 모델에 보내지 않는 것 |
| --- | --- | --- |
| 영상 없는 기획 | 브리프, 프리셋, 화면 목록, 입력 예시, 도구 목록 | 없음 |
| 이미 찍힌 영상 | 위 자료에 더해 시간표 JSON과 몇 장의 프레임 | MP4 파일 자체 |

기존 MP4가 있을 때만 `mcp-video-analyzer` CLI로 시간표, 장면 프레임, 대사, OCR을 만든다. 파일이 없으면 도구 이름은 목록에 있어도 시간표 수집 결과는 `없음`이다. 분석기는 촬영 전에 대본을 쓰지 않는다.

데스크톱 대화창 MCP는 Railway 워커에서 쓰지 않는다. Codex, Cursor, MethodIQ, Canva, 대화창에 붙은 video analyzer는 워커 경로가 아니다.

## 종류별 기본값

세 종류가 `lib/video-beats.ts`의 `videoPresets`에 있다. 자막과 음성은 공통이다.

| 항목 | 값 |
| --- | --- |
| 자막 | 하단 중앙, ASS alignment 2, 글자 크기 46, 아래 여백 64, 외곽선 14 |
| 자막 글꼴 | Linux는 Noto Sans CJK KR, Windows는 맑은 고딕 |
| 음성 | Google `ko-KR-Chirp3-HD-Kore`, 속도 0.94 |
| 보도자료 | 목표 75초, 범위 45–120초 |
| 뉴스 분석 | 목표 80초, 범위 45–120초 |
| 유튜브 제작 | 목표 70초, 범위 40–120초 |

공통 원칙은 한 장면이 한 가지를 말하고, 입력·실행·결과 순서를 지키며, 화면에 없는 수치를 만들지 않고, 규칙 기반 화면 결과를 모델이 작성했다고 말하지 않는 것이다.

도구 목록은 Chromium, HTML 카드, Google TTS, FFmpeg, Tesseract, video analyzer다. 이 목록은 1차 요청에 동봉하는 능력 목록이며, 수집 지시를 이 여섯 개로 닫지 않는다.

## 비어 있는 것

현재 워커와 `runVideoAgent`는 기획 응답을 한 번 받은 뒤 바로 촬영한다. 수집 지시를 실행하지 않고, 보고를 다음 기획 호출에 넣지 않으며, `produce`를 기다리지 않는다. `mcp-video-analyzer`는 이미지에 없다. 작업 상태도 기획, 수집, 제작으로 나뉘어 있지 않다.

## 구현 단계

### 1. 기획 계약

브리프를 목적, 길이, 대략 내용, 영상 종류로 받는다. 한 작업에 회차를 저장한다. 회차마다 기획 요약, 장면 초안, 수집 지시, 수집 보고, decision을 남긴다.

완료 기준: `produce`가 아닌 응답만으로 촬영 스크립트가 실행되지 않는다.

### 2. 수집과 보고

자유 문장 지시를 앱 능력에 연결한다. 지금 `reportCollection`의 키워드 대조를 실제 수행으로 바꾼다.

| 지시가 가리키는 것 | 앱이 하는 일 |
| --- | --- |
| 보도자료·뉴스·유튜브 화면과 입력 예시 | 가진 화면 정의와 fixture를 보고 |
| 화면을 열어 글자를 읽기 | Chromium으로 해당 화면을 열고 관찰 문자열을 확인 |
| 자막, 음성, 길이, 방법 | 그 종류의 프리셋 값을 보고 |
| 표, 차트, 도식 | HTML 카드로 만들 수 있다고 보고하고, 제작 단계에서 렌더 |
| 기존 MP4의 시간표 | 파일이 있으면 analyzer CLI, 없으면 `없음` |
| 그 외 | `없음`과 이유 |

완료 기준: 없는 자료를 거절 문구로 막지 않고 `{ order, status: "없음", detail }`로 반환한다. 있는 자료는 실제 값이나 파일 경로를 포함한다.

### 3. 기획 순환

1차 사용자 메시지는 `buildPlanningDossier` 결과다. 응답의 `decision`이 `collect`이면 2단계 보고를 붙여 같은 모델에 다시 보낸다. `produce`이면 그 회차의 문장을 제작 입력으로 고정한다.

완료 기준: 수집 보고가 다음 요청 본문에 들어가고, 3회 안에 `produce`가 없으면 영상 파일 없이 기획 기록만 `completed`가 아닌 기획 종료 상태로 남는다.

### 4. 제작

고정된 비트만 `capture-video-v2`, `render-video-v2`, `review-video-v2`로 넘긴다. 자막 위치·크기와 음성은 그 비트의 프리셋을 따른다. 화면 결과가 규칙 기반이면 내레이션이 모델 작성으로 읽히지 않게 기존 금지 표현 치환을 유지한다.

완료 기준: 확정 문장과 다른 14장면 고정 대본은 이 경로에서 쓰이지 않는다. 결과는 1920×1080, 오디오 있음, 검토 기록 `video-assets/v2/review.json`이다.

### 5. 종류별 프리셋

보도자료, 뉴스, 유튜브의 자료, 도구, 방법, 자막, 음성을 코드 상수에서 설정 데이터로 옮긴다. 새 종류는 같은 항목을 채워 추가한다. 프리셋은 1차 요청에 실릴 뿐, 수집 지시 목록을 닫지 않는다.

완료 기준: 프리셋 값을 바꾸면 1차 자료 묶음과 합성 자막·음성 인자가 같이 바뀐다.

### 6. Railway

이미지 빌드 시 `mcp-video-analyzer` CLI를 고정 설치한다. 런타임 `npx`로 받지 않는다. 캐시는 `MCP_CACHE_DIR`이다. 한국어 OCR은 `--ocr-language kor`와 이미지 안의 학습 데이터를 쓴다. 워커에는 기획용 모델 키와 Google TTS 환경 변수가 있다. 데스크톱 MCP는 이미지에 넣지 않는다.

완료 기준: 웹은 `npm start`, 워커는 `npm run worker:video`로 뜨고, MP4가 있는 작업만 분석기를 호출한다.

## 하지 않는 것

- 수집 지시를 닫힌 동사 메뉴로 제한하지 않는다.
- 화면 목록을 기획 그 자체로 쓰지 않는다. 화면 목록은 1차에 제공하는 자료다.
- 원본 MP4를 모델 API에 첨부하지 않는다.
- Creatomate 유료 구독과 데스크톱 MCP 연결은 이 계획의 범위가 아니다.
- `D:\Git\pr-studio`의 `main`(`1aa21da`, 강의 자료)은 이 앱이 아니다. 구현은 `agent/pr-studio-2.0`에서 한다.

## 합격 기준

1. 같은 앱에서 브리프가 달라지면 확정된 장면 순서와 문장이 달라진다.
2. 수집 지시는 자유 문장이고, 앱이 못 하는 지시는 `없음`으로 다음 기획에 돌아간다.
3. `produce` 이전에는 `capture-video-v2`가 실행되지 않는다.
4. 완성 영상은 그 기획의 문장과 그 종류의 자막·음성을 쓴다.
5. 규칙 기반 보도자료·뉴스·유튜브 결과를 모델이 직접 작성한 것처럼 말하지 않는다.
6. 워커 한 번으로 기획 순환과 제작이 Railway에서 끝난다.
