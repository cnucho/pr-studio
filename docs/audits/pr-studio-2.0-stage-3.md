# PR Studio 2.0 단계 3 감사

- 단계: 자료 수집기와 최대 3회 기획 순환
- 감사 기준: `docs/plans/2026-10-25-pr-studio-2.0-implementation.md`
- 대상 브랜치: `agent/pr-studio-2.0`

## 계획 감사

### 고정 목표와의 일치

기획 모델이 필요한 자료를 요청하고 실제 기능이 그 요청을 제한된 능력으로 수행한 뒤, 결과를 다음 기획 회차에 돌려주는 구조는 콘텐츠의 적절성을 높이기 위한 핵심 순환이다. 수집 자체를 제품 목적으로 확장하지 않고, 주장과 화면 설명의 근거를 확보하는 데만 사용한다.

### 수용한 의견

- 모델의 자유 문장과 실행 가능한 기능을 `capabilityId`로 분리한다.
- 등록된 수집 능력만 실행하고 알 수 없는 능력은 이유가 있는 `없음` 보고로 반환한다.
- fixture와 프리셋은 추정 설명이 아니라 실제 JSON 값을 증거로 반환한다.
- 화면 관찰은 Chromium으로 실제 앱을 열고 선택한 도구의 활성 패널만 읽는다.
- 매 회차의 수집 보고를 다음 모델 요청에 포함하고, 최대 3회를 코드에서 강제한다.
- 기존 MP4 분석은 입력 파일의 안전한 저장과 분석기 고정이 필요한 단계 7에서 연결한다. 단계 3에서는 지원한다고 가장하지 않고 `없음`으로 보고한다.

### 도구 결정

- 이미 프로젝트에서 사용하는 Playwright/Chromium을 화면 관찰에도 재사용한다.
- 임의 shell 명령을 모델 요청에 연결하지 않는다.
- 별도 외부 수집 도구는 도입하지 않았다. 현재 등록 수집기로 목표에 필요한 근거를 더 단순하고 검증 가능하게 제공할 수 있기 때문이다.

### 계획 감사 결론

단계 3은 도구 확장이 아니라 콘텐츠 근거 확보와 반복 기획의 정확성을 강화한다. 구현 진행 가능.

## 구현 감사

### 구현 결과

- fixture, 프리셋, HTML 카드 가능성, 화면 관찰, 영상 분석과 미등록 능력을 처리하는 수집기 레지스트리를 구현했다.
- fixture와 프리셋 수집기는 선택된 영상 유형의 실제 데이터를 JSON 증거로 반환한다.
- 화면 관찰 수집기는 HTTP(S) 앱 주소만 허용하고 Chromium으로 해당 탭을 연다.
- 활성 탭 버튼, 활성 도구 컨테이너와 도구 제목을 모두 확인한 뒤 해당 컨테이너의 텍스트만 증거로 반환한다.
- 수집 결과를 다음 기획 요청에 전달하고, `produce` 또는 3회 소진까지 반복하는 독립 오케스트레이터를 구현했다.
- 워커가 이 오케스트레이터를 사용하고 각 회차의 계획과 수집 보고를 기존 회차 테이블에 저장하게 했다.
- 3회 안에 제작 승인이 나지 않으면 오류 영상이나 임의 영상을 만들지 않고 `plan_exhausted`로 종료한다.

### 감사에서 발견하고 수용한 수정

1. 최초 화면 수집은 활성 탭을 확인한 뒤에도 페이지 전체 `<main>` 텍스트를 증거로 읽었다. 다른 도구의 문구가 섞여 잘못된 근거가 될 수 있었다.
   - 결정: `수용`
   - 처리: 앱의 활성 도구 section에 `data-active-tool`을 부여하고 수집 범위를 그 컨테이너로 제한했다.
2. 장시간 실행 중 남아 있던 개발 검증 서버가 새 빌드 대신 이전 메모리 상태를 제공할 수 있었다.
   - 결정: `수용`
   - 처리: 포트와 프로세스 명령줄이 현재 저장소의 Next.js 서버인지 확인한 뒤 종료하고 최신 빌드로 다시 검증했다.
3. 기존 MP4 분석기를 이 단계에서 형식만 연결하면 실제 품질 검증 없이 지원하는 것처럼 보일 수 있었다.
   - 결정: `보류`
   - 처리: 단계 7 전까지 명시적인 `없음` 보고를 유지한다.

### 자동 검증 증거

- `npm test`: 7개 파일, 75개 테스트 통과
- `npm run lint`: 통과
- `npm run build`: Next.js production build 통과
- `npm run smoke:video:collection`: 최신 production 서버를 Chromium으로 열어 보도자료 활성 패널만 수집
- 스모크 증거: `DEMO 1 보도자료 작성기 ... 입력값을 바꾸면 이곳에 결과 패키지가 정리됩니다.`
- 오케스트레이터 테스트: 첫 회차 수집 보고가 두 번째 회차에 전달되고 제작 승인 시 즉시 종료
- 오케스트레이터 테스트: 승인되지 않으면 정확히 3회 뒤 `plan_exhausted` 종료

### 남은 확인

- 실제 모델 API를 사용한 3회 순환은 외부 자격 증명이 있는 통합 환경에서 검증해야 한다.
- 실제 Supabase에 회차가 저장되고 워커 재시작 뒤 이어지는지는 단계 2의 배포 전 확인 항목과 함께 검증해야 한다.
- HTML 카드는 현재 제작 가능성만 보고하며 실제 카드 생성은 단계 5의 렌더링 경로에서 수행한다.
- 기존 MP4 분석은 단계 7에서 인증된 업로드, 작업별 파일 경로, 고정 분석기와 함께 구현한다.

### 구현 감사 결론

코드 수준의 단계 3 완료 조건을 충족했다. 수집 결과가 다음 기획에 반영되고, 가능한 수집과 불가능한 수집이 정직하게 구분되며, 제작 승인 없는 3회 소진은 영상 없이 종료된다. 단계 4의 콘텐츠 중심 매니페스트 확정으로 진입 가능.
