## 계획 감사

### 고정 목표와의 일치

UI의 목적은 제작이 진행되는 듯한 인상을 주는 것이 아니라 사용자가 콘텐츠 목적, 대상, 수집 근거, 제작 결정과 최종 검수 결과를 판단할 수 있게 하는 데 있다. 따라서 기술 도구 이름보다 기획의 판단 근거와 부족한 내용을 먼저 보여 준다.

### 구현 결정

- 시간 기반 가짜 진행은 제거하고 서버가 저장한 `phase`와 `planningRound`만 표시한다.
- 목적, 대상, 콘텐츠 유형, 목표 길이와 필수 근거를 각각 구조화해 입력한다.
- 기존 MP4는 선택 입력으로 두고 인증된 비공개 업로드 API에만 전달한다.
- 최대 3회의 기획, 항목별 콘텐츠 점검, 막는 항목과 수집 보고를 작업 조회 API에서 제공한다.
- 작업 ID는 브라우저 저장소에 남기고 재로그인 후 사용자가 명시적으로 이어서 조회할 수 있게 한다.
- `plan_exhausted`는 오류가 아니라 제작 조건을 지킨 정상 결과로 표시한다.

### 계획 감사 결론

실제 판단 자료를 드러내고 제작 보류를 실패와 구분하는 방향은 콘텐츠 우선 원칙과 일치한다. 구현 진행 가능.

## 구현 감사

### 구현 결과

- 영상 목적, 대상 시청자, 콘텐츠 유형, 목표 길이, 필수 구성·근거를 별도 필드로 연결했다.
- 선택한 MP4를 최대 25MB로 사전 확인하고 인증된 `/api/video-agent/source`에 올린 뒤 반환된 식별자만 작업에 전달한다.
- 가짜 16초 타이머를 제거하고 `queued`, `planning`, `collecting`, `producing`, `reviewing`, `completed`를 실제 작업 응답으로 표시한다.
- 작업 조회가 `video_agent_planning_rounds`를 소유권 확인 뒤 읽어 기획 계획, 수집 보고와 콘텐츠 점검을 함께 반환한다.
- 각 기획 회차의 목적, 대상, 내용 흐름, 근거, 음성, 자막과 영상 적절성을 통과·보완으로 표시한다.
- 제작을 막는 항목과 수집 결과의 있음·없음을 별도로 표시한다.
- 작업 ID를 `localStorage`에 저장하고 `이전 작업 이어보기`로 중단된 브라우저 조회를 복구한다.
- 영상이 없는 `plan_exhausted` 결과에서도 최종 기획과 보완 항목을 볼 수 있다.

### 보안·운영 감사

- 작업 조회는 기존 bearer 인증과 소유자 검사를 통과한 뒤에만 기획 회차를 조회한다.
- 브라우저에는 service role key나 원본 Storage 경로 접근 권한을 주지 않는다.
- source 업로드는 인증, MIME, 크기와 MP4 signature 검사를 유지한다.
- production은 최종 사용자 인수 전이므로 변경하지 않는다.

### 남은 최종 인수

- staging에 이 변경을 배포하고 실제 화면이 작은·큰 화면에서 읽히는지 확인한다.
- 허용된 사용자로 OTP 로그인한 뒤 MP4 업로드, 작업 생성, 페이지 재조회와 결과 다운로드를 브라우저에서 한 번 연결 검증한다.
- 이 인수 전에는 production으로 승격하지 않는다.
