# PR Studio 2.0 단계 2 감사

- 단계: 작업 상태와 회차 영속화
- 감사 기준: `docs/plans/2026-10-25-pr-studio-2.0-implementation.md`
- 대상 브랜치: `agent/pr-studio-2.0`

## 계획 감사

### 고정 목표와의 일치

작업을 먼저 저장하고 Railway 워커가 기획을 수행하도록 바꾸는 것은 콘텐츠 기획 기록의 유실을 막고, 최대 3회 검토를 실제로 지키기 위한 기반이다. 영상 화려함이나 도구 확장이 아니라 핵심 기능의 안정성에 직접 기여한다.

### 수용한 의견

- 웹 API는 큐 사용 시 모델을 호출하지 않고 작업만 생성한다.
- 기획 회차는 작업과 별도 테이블에 저장해 입력, 결과와 수집 보고를 감사할 수 있게 한다.
- 기존 `status`와 별도로 세부 `phase` 및 정상 결과인 `outcome`을 둔다.
- 워커가 웹과 같은 TypeScript 기획 코드를 사용해 계약 중복을 피한다.
- 긴 제작 명령 중에도 lease heartbeat가 실행되도록 외부 프로세스를 비동기로 실행한다.

### 도구 결정

- `tsx@4.23.15`를 고정 설치한다.
- 목적은 워커 기능 확장이 아니라 TypeScript 기획 계약을 웹과 재사용해 중복 구현 오류를 줄이는 것이다.
- Railway Node 22 이미지에서 `npm run worker:video`로 실행한다.

### 계획 감사 결론

단계 2는 고정 목표를 바꾸지 않고 핵심 기획 순환의 신뢰성을 높인다. 구현 진행 가능.

## 구현 감사

### 구현 결과

- 신규 migration에 요청, phase, outcome, 기획 회차, 최종 결정, 매니페스트와 artifact prefix를 추가했다.
- `video_agent_planning_rounds` 테이블로 최대 3회의 계획과 수집 보고를 저장한다.
- 큐 API는 모델 호출 전에 작업을 생성하고 즉시 작업 ID를 반환한다.
- 워커를 TypeScript로 전환하고 기획 계약 및 검증 코드를 직접 재사용한다.
- 저장된 회차 다음부터 기획을 재개한다.
- 최대 3회 뒤 제작 준비가 되지 않으면 `plan_exhausted` 정상 결과로 완료한다.
- `produce` 및 콘텐츠 게이트를 통과하면 매니페스트를 저장하고 제작으로 이동한다.
- heartbeat와 lock 소유권 검사를 추가했다.
- UI와 다운로드 경로가 영상 없는 `plan_exhausted` 결과를 오류 없이 처리하게 했다.

### 감사에서 발견하고 수용한 수정

1. `spawnSync`가 이벤트 루프를 막아 heartbeat가 실행되지 않았다.
   - 결정: `수용`
   - 처리: 제작 명령을 비동기 `spawn`으로 전환했다.
2. lock 소유권을 잃은 워커가 DB를 계속 갱신할 수 있었다.
   - 결정: `수용`
   - 처리: 조건부 update 결과가 없으면 lease 상실 오류를 발생시킨다.
3. Next.js 빌드는 통과해도 실제 `tsx` 실행에서 top-level await가 CommonJS 출력과 충돌했다.
   - 결정: `수용`
   - 처리: 워커 루프를 명시적인 async `main` 함수로 감쌌다.

### 자동 검증 증거

- `npm test`: 6개 파일, 72개 테스트 통과
- `npm run lint`: 통과
- `npm run build`: Next.js production build 통과
- `npm run worker:video:once`: TypeScript 변환과 모듈 로딩 성공 후 필수 Supabase 환경 변수 검사에서 의도대로 종료

### 배포 전 남은 확인

- migration은 아직 실제 Supabase/Railway 환경에 적용하지 않았다.
- 실제 DB를 사용한 claim, 회차 저장, 워커 재시작 통합 테스트가 필요하다.
- 제작 파일 경로는 아직 작업별로 격리되지 않았으며 단계 5에서 처리한다.
- 화면 관찰과 기존 영상 분석 수집기는 아직 `없음`으로 보고하며 단계 3과 단계 7에서 각각 연결한다.

### 구현 감사 결론

코드 수준의 단계 2 목표는 충족했다. 실제 환경 migration과 워커 통합 검증 전에는 Railway 배포 완료로 판단하지 않는다. 단계 3의 수집기 보강으로 진입 가능.
