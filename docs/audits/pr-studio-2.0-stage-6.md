## 계획 감사

### 고정 목표와의 일치

렌더 명령의 성공은 콘텐츠 전달의 성공이 아니다. 최종 MP4의 실제 시간표와 프레임을 승인 manifest의 목적, 근거, 내레이션과 자막에 다시 연결해야 콘텐츠 적절성을 확인할 수 있다.

### 수용할 의견

- 렌더러가 beat별 시작·종료·실제 음성 길이·화면 길이를 `timeline.json`에 기록한다.
- 검토기는 캡처 원본이 아니라 최종 MP4의 각 beat 중간 프레임을 추출한다.
- manifest와 timeline의 순서, 누락, 길이와 콘텐츠 계약 필드를 검사한다.
- 앱 화면 beat는 캡처 당시 실제 관찰 문구와 연결한다.
- OCR이 있으면 최종 프레임에서도 핵심 문구를 확인한다.
- OCR이 없는 로컬 환경은 `skipped`로 명시하고 직접 프레임 감사 결과와 구분한다. Railway에서는 설치된 한국어 Tesseract로 자동 검사를 수행한다.
- 기술 검사를 통과해도 콘텐츠 계약 불일치가 있으면 `ready`가 될 수 없다.

### 계획 감사 결론

단계 6은 최종 산출물이 의도한 기능을 실제로 발휘하는지를 확인하는 핵심 감사다. 구현 진행 가능.

## 구현 감사

### 구현 결과

- 렌더러가 각 beat의 시작·종료, 장면 길이와 실제 WAV 길이를 `timeline.json`에 기록한다.
- 시간표에는 beat ID, 화면 ID, 목적, 시청자 이해 목표, 근거, 내레이션과 자막을 함께 고정한다.
- 검토기는 캡처 원본 영상이 아니라 최종 MP4의 각 beat 중간 시점에서 프레임을 추출한다.
- manifest와 timeline의 beat 수, 순서, 콘텐츠 필드, 최소 화면 시간과 음성 길이를 대조한다.
- 전체 영상 길이가 manifest 프리셋 범위에 있는지 검사한다.
- 앱 화면 beat는 캡처 때 확인한 실제 문구와 연결한다.
- Tesseract가 있으면 최종 프레임의 OCR 문구를 `observe` 기준과 대조한다.
- 기술 준비와 콘텐츠 준비를 `technicalReady`, `contentReady`로 분리하고 둘 다 통과해야 `ready`가 된다.
- 기존 산출물처럼 timeline이 없는 경우에도 저장된 실제 WAV 길이로 시간표를 복원해 재감사할 수 있게 했다.

### 감사에서 발견하고 수용한 수정

1. 이전 검토기는 최종 MP4가 아니라 캡처 원본 WebM에서 프레임을 뽑았다. 카드, 자막과 최종 합성 결과를 실제로 보지 못했다.
   - 결정: `수용`
   - 처리: 최종 MP4 시간표 중간 지점에서 모든 beat 프레임을 추출한다.
2. 이전 `review.json`은 화면 관찰과 해상도만 검사해 내레이션·자막·목적이 승인 manifest에서 바뀌어도 감지하지 못했다.
   - 결정: `수용`
   - 처리: timeline에 콘텐츠 계약을 복제하고 manifest와 완전 대조한다.
3. 로컬 환경에는 Tesseract가 없었다.
   - 결정: `수정 수용`
   - 처리: OCR을 수행하지 않았다는 사실을 `ocrStatus: skipped`로 숨김없이 기록하고 최종 프레임을 직접 감사했다. Railway Docker에서는 설치된 한국어 Tesseract로 자동 대조하며, OCR이 실행된 환경에서 핵심 문구가 누락되면 실패한다.
