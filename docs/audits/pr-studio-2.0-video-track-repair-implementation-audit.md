# PR Studio 2.0 영상 종류 수집 불일치 구현 독립 감사

- 감사일: 2026-10-26
- 대상 커밋: `f33c09c`
- 감사 방식: 구현 주체와 분리된 독립 에이전트의 diff·테스트·실환경 증거 대조
- 결론: track 수리 승인, 전체 2.0 흐름은 후속 결함 때문에 조건부 승인

## 1. 승인된 수리

`f33c09c`는 영상 종류 소실의 직접 원인을 제거했다.

- `CollectionContext`가 필수 `track: VideoTrack`을 받는다.
- 수집기가 목적 문자열을 재추론하지 않고 `context.track`을 사용한다.
- 워커가 검증된 `brief.track`을 수집 컨텍스트에 주입한다.
- 워커 경계, 명시적 track 우선성, 세 track 화면 라우팅 테스트가 추가되었다.
- 제작 게이트, 최대 3회 제한과 콘텐츠 적절성 기준은 완화되지 않았다.

## 2. 검증 증거

- 전체 테스트: 10개 파일, 88개 테스트 통과
- lint: 통과

- Railway staging web 배포: `3d015efc-b6d2-48bd-9a3b-833e32cda6ff` 성공
- Railway staging worker 배포: `a8681b62-bd55-4fd3-a741-08ff8b0abe8b` 성공

기존 결함의 `보도자료 데모 화면` 오수집은 재현되지 않았다.

## 3. 독립 감사 발견사항

### 높음·후속 결함 — 수집 증거 생명주기

- `lib/video-orchestrator.ts`는 새 수집 결과로 기존 보고를 덮어쓴다.
- 워커 재개 경로는 저장된 마지막 라운드의 보고만 전달한다.
- 3차 기획 후에도 수집하지만 이를 판단할 4차 호출이 없어 마지막 증거가 사용되지 않는다.
- 이전 계획 요약에는 수집 보고가 포함되지 않는다.

실제 작업에서 1차 MP4 분석은 성공했지만 3차 판단이 다시 “기존 영상 분석 결과 없음”이라고 한 현상과 일치한다.

판정: track 수리와 독립된 후속 결함이지만 전체 제작 수렴을 막으므로 별도 수리가 필요하다.

### 높음·후속 결함 — 화면 수집 기능 계약 불일치

- 기획 자료는 Chromium이 입력·클릭·결과 확인·동작 녹화를 할 수 있다고 설명한다.
- 실제 화면 수집기는 탭을 연 뒤 정적 `innerText()`만 읽는다.
- 따라서 올바른 YouTube 탭을 선택해도 모델이 요구한 생성 후 대본·게시 패키지 증거를 만들 수 없다.

판정: track 수리와 독립된 후속 결함이지만 `plan_exhausted`의 직접 잔여 원인이므로 별도 수리가 필요하다.
