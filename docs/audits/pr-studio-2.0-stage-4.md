# PR Studio 2.0 단계 4 감사

- 단계: 콘텐츠 중심 매니페스트 확정
- 감사 기준: `docs/plans/2026-10-25-pr-studio-2.0-implementation.md`
- 대상 브랜치: `agent/pr-studio-2.0`

## 계획 감사

### 고정 목표와의 일치

제작기가 화면 ID와 문장만 받는 구조에서는 한 장면이 왜 필요한지, 무엇을 근거로 말하는지, 다음 장면으로 왜 넘어가는지를 잃기 쉽다. 매니페스트를 콘텐츠 계약으로 강화하면 화려한 화면보다 목적, 근거, 자연스러운 설명과 적절한 자막을 우선한다는 고정 목표가 실제 제작 입력에도 유지된다.

### 수용할 의견

- 각 beat에 장면 목적, 시청자 이해 목표, 근거, 화면 동작, 내레이션, 자막, 전환 이유를 명시한다.
- 최소 화면 시간과 예상 발화 시간을 함께 기록한다.
- 예상 발화 시간보다 짧은 화면 계획은 매니페스트 확정 단계에서 보정한다.
- 모델 문장이 허용 화면이나 실제 근거를 바꾸지 못하게 한다.
- 제작 승인 뒤의 매니페스트를 단일 제작 계약으로 사용하고, 이후 단계가 임의의 대체 문장을 만들지 않게 한다.
- 기존 캡처·렌더러와의 호환 필드는 단계 5 전까지 유지하되 새 콘텐츠 필드를 기준값으로 삼는다.

### 계획 감사 결론

단계 4는 고정 목표를 제작 데이터 구조에 직접 반영한다. 구현 진행 가능.

## 구현 감사

### 구현 결과

- 각 beat에 `purpose`, `viewerTakeaway`, `evidence`, `screenAction`, `narration`, `subtitle`, `transitionReason`을 고정했다.
- 각 beat에 `estimatedNarrationMs`와 `minScreenTimeMs`를 기록한다.
- 예상 발화 시간에 장면별 정지 시간을 더한 값보다 화면 시간이 짧지 않도록 보정한다.
- manifest에 목표·최소·최대·예상 길이를 담는 `timing`을 추가했다.
- 목적, 대상 시청자, 트랙과 목표 길이를 구조화 브리프에서 manifest와 모델 입력까지 전달한다.
- 모델은 장면 목적, 시청자 이해 목표와 전환 이유를 반드시 반환해야 한다.
- 모델 자막 길이를 80자로 제한하고 콘텐츠 계약의 누락, 발화 시간 부족, 금지 주장과 자막 길이를 제작 전 검사한다.
- 화면 근거는 모델이 쓰는 자유 문장이 아니라 등록 화면 정의에서만 가져온다.
- 기존 제작 스크립트가 사용하는 `action`, `point`, `minHoldMs`는 각각 새 필드의 호환 별칭으로 유지했다.

### 감사에서 발견하고 수용한 수정

1. 기존 manifest의 대상 시청자는 항상 `홍보 담당자`로 고정되어 구조화 브리프의 대상을 잃었다.
   - 결정: `수용`
   - 처리: API, 큐 요청, 워커, 기획 모델과 manifest를 통해 `targetAudience`를 전달한다. 이전 작업은 안전한 기본 대상과 추론 트랙으로 읽는다.
2. 기존 `point`와 새 `viewerTakeaway`를 모델이 동시에 작성하면 같은 의미를 두 번 생성하고 불일치시킬 수 있었다.
   - 결정: `수용`
   - 처리: 모델 계약에서는 `viewerTakeaway`만 받으며, `point`는 기존 UI 호환을 위한 파생 별칭으로만 남긴다.
3. 문자 수 기반 예상 발화 시간은 실제 TTS 길이와 정확히 같지 않다.
   - 결정: `수정 수용`
   - 처리: 단계 4에서는 과소 계획을 막는 사전 추정치로 사용하고, 단계 5에서 실제 생성 음성 길이를 최종 장면 시간으로 사용한다.

### 자동 검증 증거

- `npm test`: 7개 파일, 78개 테스트 통과
- `npm run lint`: 통과
- `npm run build`: Next.js production build 통과
- 기본 manifest 콘텐츠 검사: 보도자료, 뉴스, 유튜브 모두 문제 0건
- 예상 길이: 보도자료 52.5초, 뉴스 58.0초, 유튜브 46.7초로 각 프리셋 범위 안
- 구조화 브리프 테스트: 목적, 대상 시청자, 명시 트랙과 목표 길이가 manifest에 유지됨
- 기획 모델 테스트: 대상 시청자가 프롬프트와 승인 manifest에 유지됨

### 남은 확인

- 실제 TTS 발화 길이와 추정치의 차이는 단계 5에서 기록하고 보정해야 한다.
- 현재 UI는 한 문장 목적만 전송하므로 대상 시청자와 목표 길이를 직접 편집하는 입력은 단계 8에서 추가해야 한다.
- 호환 별칭은 단계 5의 캡처·렌더러 전환이 끝난 뒤 제거 여부를 판단한다.

### 구현 감사 결론

코드 수준의 단계 4 완료 조건을 충족했다. 영상 종류와 구조화 브리프가 바뀌면 목적, 대상, 장면 순서와 목표 길이가 manifest에 반영되며, 모든 장면은 목적·근거·설명·자막·전환 이유와 시간 계약을 가진다. 단계 5의 작업별 제작 경로와 실제 음성 기반 타이밍으로 진입 가능.
