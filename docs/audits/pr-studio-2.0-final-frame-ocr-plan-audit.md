# PR Studio 2.0 최종 프레임 OCR 수리 계획 독립 감사

- 감사일: 2026-10-26
- 대상 계획: `docs/plans/2026-10-26-final-frame-ocr-repair.md`
- 감사 방식: 구현 담당과 분리된 독립 검토
- 최초 판정: 수정 필요, 원안 구현 불가
- 반영 후 판정: 감사 필수 조건을 계획에 반영해 구현 진입 가능

## 핵심 발견사항

### P0 — DOM 존재가 실제 영상 가시성을 보장하지 않는다

생성 후 `getByText(...).waitFor()`와 `innerText()`가 성공해도 결과 제목이 녹화 뷰포트 아래에 있을 수 있다. 유튜브 게시 패키지는 긴 결과 페이지의 뒤쪽에 있으므로 OCR 실패를 인식 오류로만 보면 안 된다.

수용한 수정:

- 전용 관찰 marker와 유일한 locator 사용
- 결과 요소를 자막과 겹치지 않는 안전 영역으로 스크롤
- 원래 요소 box 전체가 뷰포트 안에 없으면 clamp하지 않고 캡처 실패
- 안정 구간을 실제로 녹화하고 시간 정보 보존

### P1 — 순간 노출 방지와 단일 성공 규칙의 모순

원안은 여러 샘플 중 하나만 일치해도 통과하고 첫 성공 뒤 중단하도록 되어 있어 순간 노출을 승인할 수 있었다.

수용한 수정:

- 동작 장면은 인접한 두 샘플 이상 연속 일치
- 정지 장면은 안정된 대상 영역 한 장에서 일치
- 두 종류의 합격 규칙 분리

### P1 — 샘플 시점과 결과 안정 시점이 연결되지 않는다

beat 후반이라는 상대 위치만으로는 결과가 보이는 구간을 보장할 수 없다. 동작 클립이 캡처 종료 뒤 다음 beat를 읽는 문제도 있다.

수용한 수정:

- `stableFromMs`/`stableToMs` 기록
- 렌더 소스 구간을 캡처 종료 시점에서 제한
- 안정 구간과 패딩 구간만 최종 OCR 샘플로 사용

### P1 — 제작 환경 OCR이 fail-open이다

기존 코드는 Tesseract가 없으면 OCR 누락을 빈 목록으로 만들어 콘텐츠 준비를 통과시킬 수 있다.

수용한 수정:

- 제작 경로는 Tesseract·`kor+eng`·명령 실행이 하나라도 실패하면 완료 불가
- 로컬 skip은 명시적인 개발 전용 옵션으로만 허용

### P1 — 콘텐츠 실패가 전체 재렌더를 유발한다

같은 작업의 세 번 재시도에서 OCR 누락 목록과 MP4 크기가 달라졌다. 콘텐츠 검토 실패를 일반 인프라 오류처럼 재큐잉하면 동일 산출물 재검증이 아니라 새로운 영상을 계속 만든다.

수용한 수정:

- 콘텐츠 불일치는 즉시 최종 실패, 전체 재렌더 금지
- OCR 인프라 오류는 같은 MP4 검토만 제한 재시도
- 캡처·TTS·렌더 인프라 오류만 작업 재시도
- 실패 MP4 해시, review, crop 근거 보존

### P2 — locator·좌표·회귀 계약 부족

페이지 전체의 느슨한 텍스트 locator, 불명확한 좌표 변환, 단일 성공 위주의 테스트는 오검출을 막지 못한다.

수용한 수정:

- 결과 제목 전용 `data-*` marker
- CSS 좌표부터 확대·크롭·여백까지 변환 순서 고정
- FFmpeg 변환과 검증 좌표의 공통 계약
- 화면 밖·오문구·단일 프레임·CJK OCR·반복성 테스트 추가

## 목표 정합성

감사는 화려함이나 외부 도구 사용을 목표로 추가하지 않았다. 수정안은 실제 화면 근거가 최종 영상 안에서 충분한 시간 동안 보이는지를 더 엄격하고 재현 가능하게 검사한다. 콘텐츠 적절성, 자연스러운 음성·간결한 자막, 목적에 맞는 화면이라는 고정 목표와 일치한다.

## 결론

최초 계획은 구현 불가였다. 위 필수 의견을 모두 계획에 반영했으므로 품질 게이트를 낮추지 않는 조건으로 구현 진행을 승인한다.
