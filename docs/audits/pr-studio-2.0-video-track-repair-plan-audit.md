# PR Studio 2.0 영상 종류 수집 불일치 수리 계획 독립 감사

- 감사일: 2026-10-26
- 감사 대상: `docs/plans/2026-10-26-video-track-collection-repair.md`
- 기준 커밋: `b398653`
- 감사 방식: 구현 주체와 분리된 독립 에이전트의 문서·코드 대조
- 코드 수정: 없음
- 결론: 조건부 승인

## 1. 종합 판정

근본원인과 최소 수리 방향은 타당하다. `brief.track`이 워커→수집기 경계에서 소실된 뒤 목적 문자열로 재추론되는 것이 직접 원인이며, 필수 `track: VideoTrack` 주입은 가장 작고 명확한 계약 수정이다.

제작 게이트를 우회하거나 외부 도구와 화면 효과를 추가하지 않으므로 고정 목표와 일치한다. 치명적 또는 높은 위험은 없다. 다만 자동 회귀 방지 범위에 중간 위험 2건을 포함하는 조건으로 구현 진입을 승인한다.

## 2. 발견사항과 처리

### 중간 — 워커→수집기 전달 경계 자동 테스트 누락

- 근거: 실제 결함은 `scripts/video-agent-worker.ts`가 확정된 `brief.track` 대신 `brief.purpose`를 수집기에 전달한 지점이다.
- 위험: 수집기 단위 테스트만으로는 워커가 다시 잘못된 컨텍스트를 만드는 회귀를 잡지 못한다.
- 감사 의견: 목적 문장이 press를 암시하더라도 구조화된 `brief.track: "youtube"`가 수집 컨텍스트까지 전달되는 경계 테스트가 필요하다.
- 처리: **수용**. 순수 컨텍스트 생성 함수를 분리하고 워커가 이를 사용하게 하며 경계 테스트를 추가한다.

### 중간 — 실제 실패 기능인 화면 관찰 라우팅 자동 테스트 누락

- 근거: 실제 장애는 `lib/video-collection.ts`의 화면 탭 선택에서 발생했다.
- 위험: staging 인수만으로 현재 수정은 확인할 수 있지만 이후 CI 회귀는 막지 못한다.
- 감사 의견: 세 track의 탭·제목 매핑을 순수 함수로 분리한 표 기반 테스트 또는 동등한 자동 테스트가 필요하다.
- 처리: **수용**. `press`, `news`, `youtube` 매핑 테스트를 추가한다.

### 낮음 — API 함수 명칭 표현 부정확

- 근거: API는 `planningBrief()`가 아니라 직접 `videoBriefSchema.parse()`를 호출하며, `planningBrief()`는 워커에만 있다.
- 처리: **수용**. 계획서 표현을 “API 입력 경계와 워커의 `planningBrief()`”로 수정했다.

### 낮음 — 산출물 품질 인수 기준이 추상적

- 근거: 저장소 지침은 길이·해상도·파일 크기·표본 프레임·전체 시청과 음성-화면 정렬 확인을 요구한다.
- 처리: **수용**. 영상이 생성되는 경우 표본 프레임, 최소 1회 전체 시청, 음성-화면 동기와 자막 간결성을 완료 조건에 추가했다.

## 3. 목표 적합성

- 콘텐츠 적절성: 사용자 선택과 일치하는 화면 증거를 기획에 제공하므로 개선된다.
- 음성·자막: 직접 정책을 변경하지 않으며 잘못된 화면 근거가 기획을 오염시키는 위험을 줄인다.
- 화면 적절성: 화려함이 아니라 선택 정확도를 높인다.
- 제작 안전성: `produce` 게이트와 최대 3회 제한을 그대로 유지한다.
- Railway 운영: 새 인프라나 외부 종속성을 도입하지 않는다.

## 4. 구현 진입 조건

다음 항목을 구현 범위에 포함하는 조건으로 진행할 수 있다.

1. 명시적 track을 필수 수집 계약으로 변경한다.
2. 워커 브리프→수집 컨텍스트 경계 테스트를 추가한다.
3. 세 track의 화면 관찰 라우팅 테스트를 추가한다.
4. 전체 테스트, lint, build와 Railway staging 실제 작업으로 검증한다.

이 조건은 수리 계획에 모두 반영되었으므로 구현에 진입한다.
