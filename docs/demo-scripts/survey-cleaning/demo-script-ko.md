# 설문 응답 데이터 정제 데모

## 공통 브리프

- 대상 앱: CLEANING 중앙 로그인 MCP 및 웹 검토 작업공간
- 대상자: 조사 연구원, 데이터 처리 담당자, 품질 책임자
- 언어: 한국어
- 시연 자료: 고정 합성 설문 5,000행·200변수
- 금지: 실제 응답자 자료, 확인되지 않은 자동수정, `analysis_ready=false` 상태를 완료로 표현하기

## 1부 · 왜 필요한가

정제 기준을 연구자 개인의 경험이 아니라 설문 메타와 명시된 규칙에 고정한다. 같은 자료와 기준이면 담당자의 숙련도와 무관하게 같은 후보, 같은 분모, 같은 검토 기록이 나와야 한다. 앱은 원자료를 덮어쓰지 않고 후보와 근거를 제시하며, 확인된 결정만 별도 결과물에 적용한다.

핵심 장면은 원응답 보존 정책, 진단 요약, 원자료 후보와 이유, 미해결 신호를 통과시키지 않는 분석 준비 판정, 5종 결과물이다.

## 2부 · 어떻게 사용하는가

1. CSV와 설문 메타 JSON을 함께 등록한다.
2. 원응답 보존 정책으로 진단한다.
3. 프로파일, 전체·유효 분모가 분리된 빈도와 교차표를 먼저 본다.
4. 후보의 원값, 규칙, 분기 조건을 확인하고 필요한 결정만 기록한다.
5. 변경 요약을 확인한 뒤 결과물을 생성한다.
6. Parquet, 갱신 메타, 감사로그, QC 보고서, 검토 워크스페이스를 저장한다.
7. `analysis_ready=false`이면 남은 차단 신호를 해소하기 전 분석으로 넘기지 않는다.

## 검증 수치

- 입력: 5,000행, 201열(응답 ID 포함), 메타 변수 200개
- 프로파일: 메타 미매칭 0개
- 빈도 D02: 전체 5,000, 유효 4,953, 결측 47
- 교차표 D02×D03: 유효쌍 4,913
- 중복 ID 0, 빈 ID 0
- 규칙 신호 9,747, 검토 후보 4,710
- 무변경 확정: change_count 0
- 분석 준비: false, 미해결 후보 4,710
- 산출물: Parquet, 메타 JSON, 감사 JSON, QC HTML, 검토 HTML
