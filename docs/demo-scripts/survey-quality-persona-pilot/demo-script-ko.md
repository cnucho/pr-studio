# 설문 품질검토 + Persona Pilot 소개 영상

## 목적과 대상

- 대상: 웹 설문을 직접 검수해야 하는 연구원과 프로젝트 매니저
- 핵심 문제: 설문 초안이 아니라 실제 응답자가 보게 될 웹 설문을 검증하기 어렵다.
- 핵심 약속: 코드 오류, 분기 위험, 응답자의 이해 위험을 조사 시작 전에 한 흐름에서 확인한다.
- 주의: 합성 응답은 실제 모집단 추정치가 아니다. 문항·용어·보기·분기를 사전 점검하는 파일럿 신호다.

## 영상 구성

### 1부. 왜 필요한가

1. 설문은 웹에 올라간 뒤에도 수정된다.
2. 연구원은 문구와 보기뿐 아니라 실제 웹 설문의 참조와 분기까지 다시 확인해야 한다.
3. 분기가 작동한다고 해서 분기가 적절한 것은 아니다. 한 응답이 이후 설문을 크게 바꾸는 중요 분기는 별도 경고가 필요하다.
4. 코드가 정상이어도 응답자는 용어를 다르게 이해하거나 보기에서 답을 찾지 못할 수 있다.
5. 따라서 웹 설문 자체 검토, 중요 분기 점검, 합성 파일럿을 이어서 수행한다.

### 2부. 사용법

1. 실제 운영할 `question.js` 또는 `questions.json`을 올린다.
2. 원본 설문지는 선택 사항이다. 앱은 웹 설문 자체를 먼저 검토한다.
3. 문항 정의, 보기, 참조, 분기와 복원 일관성을 확인한다.
4. 중요 분기와 응답 경로 위험을 확인한다.
5. Persona Pilot에서 모집단 설정과 표본 크기를 정하고 합성 파일럿을 실행한다.
6. 문항별 응답 분포, 이해 난이도, 애매한 용어, 보기 누락과 피로 신호를 확인한다.
7. 문제가 있는 문항을 고친 뒤 같은 흐름으로 다시 검증한다.

## 장면별 내레이션

### 장면 1 — 웹 설문이 완성된 뒤에도 검수는 끝나지 않습니다

설문 초안이 확정되어도, 실제 웹 설문이 그대로 구현되었다고 장담하기는 어렵습니다. 문구가 바뀌고, 보기가 빠지고, 분기 조건이 달라질 수 있습니다.

### 장면 2 — 연구원이 실제로 확인해야 할 것

연구원은 원본과 같은지만 보는 것이 아닙니다. 문항 자체에 오류가 없는지, 보기가 충분한지, 참조와 분기가 맞는지, 응답자가 끝까지 자연스럽게 진행할 수 있는지를 확인해야 합니다.

### 장면 3 — 초안보다 실제 웹 설문을 먼저 봅니다

이 도구는 원본 설문지보다, 응답자가 실제로 만나게 될 웹 설문을 먼저 검토합니다. 원본 대조는 필요할 때 추가할 수 있지만, 원본에 오류가 있어도 그대로 통과시키지는 않습니다.

### 장면 4 — 작동하는 분기와 좋은 분기는 다릅니다

분기 코드가 실행된다고 해서 설계가 안전한 것은 아닙니다. 한 문항의 응답이 이후 설문을 크게 바꾸는 중요 분기라면, 잘못 선택했을 때 되돌릴 기회가 있는지도 함께 살펴야 합니다.

### 장면 5 — 실제 조사 전에 응답자의 반응을 미리 봅니다

코드가 정상이어도 응답자는 용어를 다르게 이해할 수 있습니다. 합성 파일럿은 모집단 설정에 맞춘 가상 응답으로, 애매한 표현과 보기의 빈틈, 비정상적인 분포와 피로 가능성을 조사 전에 찾습니다.

### 장면 6 — 한 번의 검수가 아니라 이어지는 검증 흐름입니다

웹 설문 자체를 검토하고, 중요 분기를 확인한 뒤, 합성 파일럿으로 응답자의 이해 위험을 봅니다. 발견한 문제를 고치고 다시 실행하면 됩니다.

### 장면 7 — 실제 운영 파일을 올립니다

사용법은 간단합니다. 실제 운영할 퀘스천 제이에스, 또는 퀘스천스 제이슨 파일을 올립니다. 원본 설문지는 선택 사항입니다.

### 장면 8 — 먼저 코드와 구조를 확인합니다

이 예시는 문항 다섯 개가 모두 복원되었고, 결정적인 정의 오류는 발견되지 않았습니다. 즉, 코드와 구조만 보면 설문은 실행 가능한 상태입니다.

### 장면 9 — 같은 설문으로 합성 파일럿을 실행합니다

이제 같은 설문을 퍼소나 파일럿으로 보냅니다. 공식 통계 기반의 모집단 구조와 필요한 표본 크기를 정하고, 합성 응답을 생성합니다.

### 장면 10 — 코드가 찾지 못한 이해 위험을 확인합니다

열두 명의 시험 표본에서, 종사상 지위와 전반적인 근무 여건이 애매한 표현으로 나타났습니다. 서비스의 범위가 불분명한 문항은 이해 난이도도 가장 높았습니다.

### 장면 11 — 결과를 수정 행동으로 연결합니다

연구원은 위험 신호가 나온 문항만 고치면 됩니다. 용어를 풀어 쓰고, 질문의 범위를 분명히 하고, 필요한 보기를 보완한 뒤 다시 검증합니다.

### 장면 12 — 조사 시작 전에 세 가지 위험을 줄입니다

이제 연구원은 웹 구현 오류, 중요 분기 위험, 응답자의 이해 문제를 조사 시작 전에 확인할 수 있습니다. 설문 검수는 경험에만 의존하는 마지막 확인이 아니라, 반복할 수 있는 품질관리 과정이 됩니다.

- 제공자: Google Cloud Text-to-Speech
- 언어: 한국어
- 음성: 남성 `ko-KR-Chirp3-HD-Charon`
- 말하기 속도: `0.94`
- 문장부호와 짧은 문장으로 띄어읽기와 호흡을 제어한다.
