# 설문조사 플랫폼 실전 튜토리얼 시리즈

## 대상과 목적

- 대상: 플랫폼 도입을 검토하거나 실제 운영을 맡을 조사기획자, 설문 작성자, QC 담당자, 분석자, 보고서 작성자
- 형식: 한국어 내레이션이 포함된 6부작 실전 튜토리얼
- 목표: 기능 소개에 그치지 않고 각 단계에서 무엇을 입력하고, 무엇을 확인하며, 어떤 산출물을 다음 단계에 넘기는지 설명한다.
- 라이브 기준 URL: `https://survey-workflow-orchestrator-production.up.railway.app`

## 전체 흐름

```text
질문 입력 → 질문 검토·검증 → 응답 배포 → 원자료 검증·정제 → 분석 → 보고서
```

각 단계의 결과는 다음 단계의 입력이 된다. 튜토리얼에서는 저장·내보내기·영수증(receipt)·경고를 함께 설명하여, 화면 조작뿐 아니라 업무 인계 기준도 보여준다.

## 1편 — 설문 입력

핵심 질문: 빈 설문을 어떻게 실무에 사용할 수 있는 질문지로 만드는가?

- 라이브러리·템플릿·파일 가져오기 중 시작 방법 선택
- 변수 ID, 질문 유형, 필수 여부, 선택지, 범위, 다국어 라벨 확인
- 로스터·매트릭스·분기 조건처럼 복잡한 질문 구성
- 오류 카운터 확인 후 저장 및 플랫폼용 draft export
- 주의: 이 화면은 질문 작성 단계이며 여기서 곧바로 공개하지 않는다.

## 2편 — 설문 검토 및 확인

핵심 질문: 질문지가 응답자에게 공개되기 전에 무엇을 검사해야 하는가?

- 프로젝트/draft JSON 불러오기 또는 샘플 검토
- 질문 유형, 필수 조건, 숫자 범위, 분기 논리, 번역 완성도 검사
- Findings를 오류·경고·정보로 구분
- blocking finding을 우선 수정하고 revision plan 확인
- 검토 receipt를 저장하여 배포 승인 근거로 사용

## 3편 — 응답받기 위한 배포

핵심 질문: 검토된 질문지를 모바일·태블릿·PC 응답 화면으로 어떻게 전달하는가?

- runtime package 또는 distribution bridge 불러오기
- 한 화면 한 문항/그룹 화면/adaptive layout 선택
- 필수응답 처리, 검증 시점, 진행률, paradata 정책 설정
- 개인정보 안내와 시작문 삽입
- distribution package 생성 후 respondent preview에서 실제 흐름 확인

## 4편 — 응답자료 검증 및 정제

핵심 질문: 수집된 원자료를 분석 가능한 데이터로 만들 때 무엇을 자동화하고 무엇을 사람이 판단하는가?

- raw response dataset 불러오기 또는 샘플 사용
- 기본 규칙과 조사별 정제 profile 적용
- 범위 오류, 논리 불일치, 중복, 누락, 검토 필요 플래그 확인
- 자동수정 결과와 사람 검토 대상 분리
- cleaning receipt와 cleaned dataset을 함께 보관
- 주의: 원자료는 덮어쓰지 않고 정제본과 처리 이력을 별도로 남긴다.

## 5편 — 분석

핵심 질문: 정제된 자료와 메타데이터를 재현 가능한 분석표와 차트 작업으로 어떻게 바꾸는가?

- analysis-ready reference, metadata output, cleaned rows 입력
- 전체/부분 전략과 segment specification 설정
- 변수·세그먼트·가중치가 포함된 교차표 작업 정의
- 자동 생성된 tasks, warnings, preview tables 검토
- analysis task package와 table/chart DSL 내보내기
- 주의: 통계적 해석 전에 분모, 가중치, 결측 처리와 검증 경고를 확인한다.

## 6편 — 보고서 작성

핵심 질문: 검증된 집계표를 근거가 남는 보고서 패키지로 어떻게 전환하는가?

- verified table/chart DSL과 verification receipt 입력
- 표별 핵심 요약과 경고 확인
- 과도한 인과해석·미검증 수치·작은 표본 경고 확인
- summary receipt와 report package 생성
- 표·차트·설명·검증 근거가 함께 전달되는지 최종 확인

## 영상 제작 기준

- 각 편은 실제 라이브 화면을 1920×1080으로 녹화한다.
- 화면이 바뀐 뒤 최소 0.8초 정지하여 시청자가 결과를 읽게 한다.
- 자막은 전체 문장 전사가 아니라 현재 단계와 핵심 판단만 표시한다.
- 조밀한 결과 화면은 속도를 높이지 않고 여러 장면으로 나눈다.
- 생성물은 `out/survey-platform-tutorial/`에 저장하고 Git에는 커밋하지 않는다.
- 최종 검증은 해상도, 길이, 오디오, 샘플 프레임, 화면-내레이션 정렬을 포함한다.
